# RTK — Rust Token Killer & Runtime Token Compression

**RTK (Rust Token Killer)** is a CLI proxy and token reduction engine designed to strip non-essential terminal noise, ANSI color codes, repeated stack trace frames, and verbose build headers before command output enters the AI agent's context window.

## Why RTK Matters

Commands like `git status`, `git diff`, `npm test`, `pytest`, `docker build`, or `cargo check` often dump hundreds of lines of boilerplate. Over a multi-turn conversation, raw command outputs consume up to **70% of total context tokens**, causing context truncation, high latency, and elevated API costs.

RTK compresses output at execution time, preserving 100% of errors, warnings, stack roots, and failure messages while stripping fluff.

---

## Key Principles & Compression Targets

### 1. Terminal Output Filtering
- **ANSI Escape Codes**: Strips raw color/formatting bytes (`\x1b[32m`, `\x1b[0m`).
- **Duplicate Stack Traces**: Deduplicates repetitive framework frame traces (e.g. node_modules / internal stdlib frames), keeping only application-level failing line numbers.
- **Progress Bars & Spinners**: Filters out dynamic spinners and progress frames (`[===>   ] 45%`).
- **Verbose Build Headers**: Summarizes dependency compilation logs into a single counts line (`Compiled 42 packages in 3.1s`).

### 2. Smart Command Proxies

| Standard Command | RTK Proxy Command | Savings | What is Kept |
|------------------|-------------------|---------|--------------|
| `git status` | `rtk git status` / `rtk status` | ~70% | Modified/untracked file list without explanatory header text |
| `git diff` | `rtk git diff` / `rtk diff` | ~60% | Changed lines & line numbers, skipping unchanged context blocks |
| `npm test` / `vitest` | `rtk npm test` | ~85% | Failing assertions & failing line numbers only; passing tests summarized |
| `pytest` | `rtk pytest` | ~85% | Failed test names, exact tracebacks, and final count line |
| `cargo check` | `rtk cargo check` | ~80% | Errors and warnings with line paths; success boilerplate stripped |
| `tsc` / `eslint` | `rtk lint` | ~75% | Error code, file path, line:col, and error message |

## Operating Modes

### Mode 1: Transparent Proxying
Wrap terminal execution commands with `rtk` prefix when invoking terminal tools (`run_command`):
```bash
# Instead of raw verbose command:
npm test

# Use RTK compressed execution:
rtk npm test
```

### Mode 2: Pipe Compression
Pipe long outputs through `rtk filter`:
```bash
cat build.log | rtk filter --level=error
```

### Mode 3: Diff Summary
Generate ultra-compact git diff summaries:
```bash
rtk diff --stat-only
```

## Integration with Caveman & Ponytail

- **RTK + Caveman**: RTK compresses the **input/environment context** coming into the agent; Caveman compresses the **output prose** generated by the agent. Together they reduce total token throughput by over 80%.
- **RTK + Spec-Kit**: When running verification steps in Spec Kit (`/speckit.verify`), use RTK proxying to keep test outputs compact.
- **RTK + Token-Savings**: Keeps session context clean, preventing context window drift across long coding sessions.
